**POST PROCESSING EFFECT PROCESS**
### 📦 1. Resource Setup: The Input and Output Images

You need two main image resources for this technique. Crucially, the output image must be created with both `VK_IMAGE_USAGE_SAMPLED_BIT` and `VK_IMAGE_USAGE_STORAGE_BIT` so you can write to it directly from the compute shader [](https://raw.githubusercontent.com/Vovan675/Vulkan/refs/heads/patch-compile-shaders/examples/computeshader/computeshader.cpp#1)[](https://blog.csdn.net/qq_35312463/article/details/106029755?utm_term=vulkan#1).

- **Input Image**: This is your rendered frame. It's a standard texture you'll sample from in the shader.
    
- **Output Image**: This is where the edge-detected result will be stored. It must be created with a `VK_IMAGE_LAYOUT_GENERAL` layout to be compatible with storage images [](https://raw.githubusercontent.com/Vovan675/Vulkan/refs/heads/patch-compile-shaders/examples/computeshader/computeshader.cpp#1).
    

It is also common practice to use a separate compute queue to handle these operations, especially if your graphics queue is heavily utilized [](https://blog.csdn.net/qq_35312463/article/details/106029755?utm_term=vulkan#1).

### 🎯 2. Descriptor Sets and Pipeline Layout

You will need to create a descriptor set layout that contains the bindings for your input and output images [](https://github.com/playcanvas/engine/blob/498c84873a0426893d1810b351f9e57bde20ef59/examples/src/examples/compute/edge-detect.compute-shader.wgsl#1)[](https://blog.csdn.net/qq_35312463/article/details/106029755?utm_term=vulkan#1).

cpp

// Example descriptor set layout binding for the input texture
VkDescriptorSetLayoutBinding inputBinding{};
inputBinding.binding = 0;
inputBinding.descriptorType = VK_DESCRIPTOR_TYPE_COMBINED_IMAGE_SAMPLER;
inputBinding.descriptorCount = 1;
inputBinding.stageFlags = VK_SHADER_STAGE_COMPUTE_BIT;
// Example descriptor set layout binding for the output storage image
VkDescriptorSetLayoutBinding outputBinding{};
outputBinding.binding = 1;
outputBinding.descriptorType = VK_DESCRIPTOR_TYPE_STORAGE_IMAGE;
outputBinding.descriptorCount = 1;
outputBinding.stageFlags = VK_SHADER_STAGE_COMPUTE_BIT;

### ✍️ 3. The Compute Shader (GLSL)

This is the heart of the effect. The compute shader is dispatched for each pixel in the output image. It samples a neighborhood of pixels from the input image and applies the Sobel operator to detect edges [](https://github.com/playcanvas/engine/blob/498c84873a0426893d1810b351f9e57bde20ef59/examples/src/examples/compute/edge-detect.compute-shader.wgsl#1)[](https://web.archive.org/web/20220529190644/https%3a/interplayoflight.wordpress.com/2022/05/29/accelerating-raytracing-using-software-vrs/#1).

glsl

#version 450
layout(local_size_x = 8, local_size_y = 8, local_size_z = 1) in;
layout(binding = 0) uniform sampler2D inputImage;
layout(binding = 1, rgba8) uniform writeonly image2D outputImage;
void main() {
    ivec2 pixel = ivec2(gl_GlobalInvocationID.xy);
    ivec2 imageSize = textureSize(inputImage, 0);
    // 1. Clamp to avoid out-of-bounds writes
    if (pixel.x >= imageSize.x || pixel.y >= imageSize.y) {
        return;
    }
    // 2. Sample the 3x3 neighborhood
    vec2 texelSize = 1.0 / vec2(imageSize);
    float samples[9];
    int index = 0;
    for (int y = -1; y <= 1; y++) {
        for (int x = -1; x <= 1; x++) {
            vec2 offset = vec2(float(x), float(y)) * texelSize;
            vec2 uv = (vec2(pixel) + 0.5) * texelSize + offset;
            vec3 color = texture(inputImage, uv).rgb;
            // Convert to grayscale using luminance weights [citation:1][citation:5]
            samples[index] = dot(color, vec3(0.299, 0.587, 0.114));
            index++;
        }
    }
    // 3. Apply the Sobel operator [citation:1][citation:5][citation:8]
    float gx = -samples[0] + samples[2] - 2.0 * samples[3] + 2.0 * samples[5] - samples[6] + samples[8];
    float gy = -samples[0] - 2.0 * samples[1] - samples[2] + samples[6] + 2.0 * samples[7] + samples[8];
    float edgeStrength = sqrt(gx * gx + gy * gy);
    // 4. Write the result to the output image
    // Clamp the edge strength and use it to color the pixel [citation:1]
    float edgeAmount = clamp(edgeStrength * 3.0, 0.0, 1.0);
    vec3 finalColor = mix(vec3(1.0, 1.0, 1.0), vec3(1.0, 0.0, 0.0), edgeAmount);
    imageStore(outputImage, pixel, vec4(finalColor, 1.0));
}

### 🚀 4. Dispatching the Compute Shader

With your pipeline created and descriptor sets bound, you can dispatch the compute shader. The number of work groups is determined by the size of your output image and the workgroup size defined in the shader [](https://github.com/playcanvas/engine/blob/498c84873a0426893d1810b351f9e57bde20ef59/examples/src/examples/compute/edge-detect.compute-shader.wgsl#1)[](https://blog.csdn.net/qq_35312463/article/details/106029755?utm_term=vulkan#1).

cpp

// imageSize is the width and height of your output image
// 8 and 8 come from the local_size_x and local_size_y in the shader
uint32_t groupCountX = (imageWidth + 7) / 8;
uint32_t groupCountY = (imageHeight + 7) / 8;
vkCmdDispatch(commandBuffer, groupCountX, groupCountY, 1);

### 🔀 5. Displaying the Result

After the compute shader has finished, you need to transition the output image to a layout suitable for sampling before you can use it in a graphics pipeline to display it on screen [](https://github.khronos.org/Vulkan-Site/samples/latest/samples/extensions/compute_shader_derivatives/README.html)[](https://raw.githubusercontent.com/Vovan675/Vulkan/refs/heads/patch-compile-shaders/examples/computeshader/computeshader.cpp#1). This typically involves using `VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL`.

### ⚡️ 6. Advanced Considerations

- **Performance**: To optimize performance, you can load the 3x3 neighborhood for multiple pixels into fast, on-chip **shared memory** (using `shared` variables in GLSL). This prevents redundant texture fetches [](https://streamhpc.com/blog/2026-07-22/image-upscaling-using-convolutional-neural-networks-in-vulkan/).
    
- **Specialization Constants**: If you plan on creating multiple edge-detection pipelines with different parameters (e.g., different kernel sizes), you can use **specialization constants** to compile variations of the shader at pipeline creation time for better performance [](https://streamhpc.com/blog/2026-07-22/image-upscaling-using-convolutional-neural-networks-in-vulkan/)[](https://www.packtpub.com/en-us/product/mastering-graphics-programming-with-vulkan-11-9781803244792/chapter/chapter-9-implementing-variable-rate-shading/summary#1).
    
- **Hardware Acceleration**: On supported hardware, the `VK_QCOM_image_processing` extension provides dedicated instructions like `OpImageBoxFilterQCOM` and `OpImageSampleWeightedQCOM` which can perform these filtering operations more efficiently [](https://docs.vulkan.org/features/latest/features/proposals/VK_QCOM_image_processing.html).
    

### ⚖️ A Note on Compute Shader Derivatives

There is a related technique that uses a dedicated extension, `VK_KHR_compute_shader_derivatives`. This allows you to use fragment-shader-like derivatives (e.g., `ddx`, `ddy`) directly inside a compute shader. While not a Sobel operator, this can be used for spatial analysis and edge detection and is demonstrated in the official Vulkan samples [](https://github.khronos.org/Vulkan-Site/samples/latest/samples/extensions/compute_shader_derivatives/README.html).
